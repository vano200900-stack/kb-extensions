# Таблицы и блок-схемы для базы знаний Битрикс24

Локальное приложение добавляет в библиотеку блоков два блока — «Таблица» и «Блок-схема» — и кнопку редактирования у каждого из них. Редактор открывается в слайдере поверх страницы.

## Что умеет

**Таблица.** Добавление и удаление строк и столбцов, шапка и выделенный первый столбец, выравнивание по столбцам, три варианта оформления (зебра, сетка, минимум). Диапазон, скопированный из Excel или Google Таблиц, вставляется сразу по ячейкам. Tab переходит к следующей ячейке, в конце таблицы добавляет строку. Текст ячеек можно править и прямо на странице, без открытия редактора — правки подхватятся при следующем открытии.

**Блок-схема.** Описание схемы на языке Mermaid с живым предпросмотром, четыре шаблона (процесс с ветвлением, дорожки «кто что делает», диаграмма последовательности, дерево), построение схемы из простого списка шагов, три цветовые темы. При сохранении схема превращается в PNG в двойном разрешении и загружается в блок. Исходный код схемы хранится в приложении, поэтому её можно открыть и доработать.

## Установка

1. Разместите папку на любом хостинге с HTTPS: GitHub Pages, свой сервер, Яндекс Object Storage. Проверьте, что `https://ваш-адрес/index.html` открывается — вне Битрикс24 он запустится в демо-режиме (`?demo=diagram` — редактор схем).
2. В Битрикс24: **Приложения → Разработчикам → Другое → Локальное приложение**.
   - Тип: серверное.
   - Путь вашего обработчика и Путь для первоначальной установки: `https://ваш-адрес/index.html`.
   - Права: **landing** (Сайты). Если в списке есть отдельное право для баз знаний — отметьте и его.
3. Сохраните, откройте приложение и нажмите «Установить блоки», затем «Завершить установку».
4. На странице базы знаний: «Добавить блок» → раздел «Текст» → «Таблица» или «Блок-схема». У блока появится кнопка «Редактировать таблицу» / «Редактировать схему».

Нажимать «Установить блоки» повторно безопасно: блоки обновятся (`RESET: 'Y'`), уже вставленные таблицы и схемы сохранятся, так как их содержимое хранится в самих блоках.

## Как это устроено

| Шаг | Метод REST |
|---|---|
| Регистрация блоков в библиотеке | `landing.repo.register` |
| Кнопка в меню блока | `landing.repo.bind` с местом встраивания `LANDING_BLOCK_…` |
| Чтение таблицы из блока | `landing.block.getcontent` |
| Запись таблицы | `landing.block.updatecontent` |
| Загрузка картинки схемы | `landing.block.uploadfile` → `landing.block.updatenodes` |
| Обновление блока в редакторе страницы | `BX24.placement.call('refreshBlock')` |
| Настройки и код схем | `app.option.set / get` |

Оформление таблицы записывается инлайн-стилями, без `<style>` и скриптов — так оно не зависит от темы сайта и проходит санитайзер блоков.

## Что проверить при первом запуске

Часть поведения REST для баз знаний документирована скупо, поэтому в коде есть страховки, но на вашем портале стоит проверить три вещи:

- **Блоки видны в библиотеке базы знаний.** В манифесте указан тип `knowledge` и `group`. Если блоки видны только в «Сайтах», напишите мне, что показывает установка, — поправим манифест.
- **Кнопка редактирования появилась у блока.** Документация допускает разный формат кода места встраивания, поэтому приложение регистрирует оба варианта и пишет в журнал установки, какой сработал.
- **Сохранение проходит.** Методы `landing.block.*` для страниц базы знаний иногда требуют параметр `scope`; приложение само пробует варианты `knowledge` и `group`. Если сохранение не проходит, текст ошибки будет во всплывающем сообщении.

## Ограничения

- Объединения ячеек нет — его нельзя надёжно сохранить при правке ячеек прямо на странице.
- Схемы с HTML-подписями (mindmap и некоторые другие типы Mermaid) нельзя сохранить картинкой — приложение предупредит. Flowchart и sequenceDiagram работают.
- Если на странице поменять картинку схемы вручную, приложение об этом не узнает и при следующем сохранении перезапишет её схемой из своего кода.
